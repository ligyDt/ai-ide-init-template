# 项目专属规则

> 复制模板后按项目实际情况补充。规则必须可执行、可验证、可解释；禁止写入真实凭据或生产资源地址。

CodeBuddy 原生项目规则位于 `.codebuddy/rules/<规则名>/RULE.mdc`。本文件保留跨 Skills 可读的规则摘要；若两者存在细节差异，以 `.codebuddy/rules/` 中更具体的规则为准。

## 工程规范

- 命名、格式化、Lint、测试命令以项目已有工具链为准。
- 新增公共接口、数据模型、跨模块依赖或第三方服务时，必须记录影响范围与回滚方式。
- 临时方案必须标注原因、风险、负责人或后续处理条件，避免长期沉淀为隐性技术债。
- 前端、后端、安全、通用协作等细分规则优先沉淀到 `.codebuddy/rules/`，并按 `alwaysApply`、`enabled` 与 `globs` 控制生效范围。

## 禁止清单

- 禁止硬编码密钥、连接串、真实域名、生产标识和真实用户数据。
- 禁止绕过测试、类型检查、安全检查或发布审批。
- 禁止未确认环境就执行外部写入、支付、部署、基础设施变更或生产访问。

## 依赖与许可证

- 新增依赖前确认用途、维护状态、安全风险和许可证。
- 优先选择 MIT、Apache-2.0、BSD、ISC 等低风险许可证。
- GPL、AGPL、未知许可证或高危漏洞依赖必须先提交审查结论。

## CodeBuddy 原生工作流

- 高频重复任务使用 `.codebuddy/commands/` 中的项目命令封装，例如需求收敛、交付计划、安全审查和 PR 汇总。
- 复杂功能、架构设计、多文件协同、UI/UX 设计、存量项目改造和复杂任务拆解，优先使用 Plan Mode；完成的计划会沉淀到 `.codebuddy/plans/`。
- 快速 Bug 修复、单文件局部调整、代码解释和小范围优化可使用 Craft Mode。
- `.codebuddy/models.json` 仅保存项目级模型显示控制或非敏感占位；不得提交真实 API Key。
