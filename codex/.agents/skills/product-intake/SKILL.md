# 产品需求收敛

将尚未定型的方向转化为工程可接手、用户可验收的需求基线。

## 流程

1. 阅读 `AGENTS.md` 并检查当前仓库状态，区分既有能力与尚未决定的事项。
2. 提取目标用户、要解决的问题、预期价值、核心流程、输入、输出、成功指标与范围边界。
3. 识别影响实现的约束：技术栈、数据来源、权限、成本、隐私、第三方服务、运行频率与交付环境。
4. 对外部数据、账号访问、支付、发布或生产访问，明确允许环境、审批要求和禁止动作；需要时调用 `$security-risk-review`。
5. 仅针对无法从仓库或用户描述中获得、且会影响架构或范围的决策向用户提问。
6. 在关键信息齐备后，输出需求基线；需要跨角色执行时交给 `$delivery-orchestration`。

## 输出

- 目标与目标用户
- 核心场景与期望结果
- 范围内与范围外事项
- 输入、输出及关键约束
- 风险与待确认事项
- 可验证的验收标准

## 停止条件

需求的目标、范围、约束或高风险授权未明确时，不创建应用代码、不连接外部写入能力、不推断生产方案。
