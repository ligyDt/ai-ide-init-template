# 项目专属规则

> 复制模板后按项目实际情况补充。规则必须可执行、可验证、可解释；禁止写入真实凭据或生产资源地址。

TRAE 原生项目规则位于 `.trae/rules/`，本文件保留跨 Agent Skills 可读的规则摘要。若两者存在细节差异，以 `.trae/rules/` 中更具体的项目规则为准。

## 工程规范

- 命名、格式化、Lint、测试命令以项目已有工具链为准。
- 新增公共接口、数据模型、跨模块依赖或第三方服务时，必须记录影响范围与回滚方式。
- 临时方案必须标注原因、风险、负责人或后续处理条件，避免长期沉淀为隐性技术债。
- 前端、后端、安全、提交信息等细分规则优先沉淀到 `.trae/rules/`，并按 TRAE 支持的 `globs`、`alwaysApply` 或 `scene` 控制生效范围。

## 禁止清单

- 禁止硬编码密钥、连接串、真实域名、生产标识和真实用户数据。
- 禁止绕过测试、类型检查、安全检查或发布审批。
- 禁止未确认环境就执行外部写入、支付、部署、基础设施变更或生产访问。

## 依赖与许可证

- 新增依赖前确认用途、维护状态、安全风险和许可证。
- 优先选择 MIT、Apache-2.0、BSD、ISC 等低风险许可证。
- GPL、AGPL、未知许可证或高危漏洞依赖必须先提交审查结论。

## TRAE 原生工作流

- 高频重复任务使用 `.trae/commands/` 中的项目命令封装，例如需求收敛、交付计划、安全审查和 PR 汇总。
- 系统级任务使用 `/spec` 生成 `.trae/specs/<任务名>/spec.md`、`tasks.md` 与 `checklist.md`，确认后再执行。
- 中小型功能或模块级重构使用 `/plan` 生成 `.trae/documents/plan.md`，确认后按计划推进。
- `.agents/skills/` 中的通用 Skills 需要在 TRAE 设置中启用 `.agents` 技能目录；若与 `.trae/skills/` 重名，TRAE 原生项目 Skill 优先。
